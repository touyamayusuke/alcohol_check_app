# アルコールチェックアプリ 要求定義

## 1. 背景

業務で運転を行う社員について、アルコールチェックを実施し、
その結果を記録・管理する必要がある。

現在の紙や口頭による管理では、

- 記録に手間がかかる
- 過去の記録を探しにくい
- 記入漏れが発生する可能性がある
- 誰が確認したのか分かりにくい

- 特に記録忘れが多々起こっている

といった問題がある。

そのため、Webアプリケーション上で簡単に
アルコールチェックを記録・確認できる仕組みを作る。

---

## 2. 目的

社員が毎日のアルコールチェックを簡単に記録でき、
管理者が記録状況を確認できるようにする。

また、アルコールチェックの記録をデータとして保存することで、
過去の記録を容易に確認できるようにする。

---

## 3. 利用者

### 一般社員

アルコールチェックを受ける人。

主な操作：

- 出社時のアルコールチェックを登録する
- 帰社前のアルコールチェックを登録する
- 自分の過去の記録を確認する

### 確認者

アルコールチェックの結果をその場で確認する社員。

固定の役割ではなく、チェックのたびに実施者がその場で選ぶ。
専任の管理者ではなく、その場にいる近くの社員が確認者となる。
確認者専用のアカウント種別や権限はない（すべての社員が確認者になれる）。

安全運転管理者は、社内規程により全社員をあらかじめ補助者として選任済みである
（この前提のもとでシステムが何を作る・作らないかは `02-要件.md` を参照）。

主な操作：

- その場でアルコールチェックの結果を目視・検知器で確認する
- 実施者の登録画面で確認者として選ばれ、記録に名前が残る

### 管理者

会社全体のアルコールチェック記録を管理する人。

主な操作：

- 社員一覧で、その日にまだ記録していない社員（出社時・帰社前の未実施）を確認する
- 全社員のアルコールチェック記録を確認する
- 過去の記録を絞り込んで探す

---

## 4. 基本的な業務フロー

1. 社員が出社する
2. アルコールチェックを実施する
3. 近くの社員に結果を確認してもらう
4. 実施者が、測定結果と確認者（確認してくれた社員）を一緒に登録する
5. 業務を行う
6. 帰社前に再度アルコールチェックを行う
7. 同様に、測定結果と確認者を登録する

原則として1日2回、

- 出社時
- 帰社前

のアルコールチェックを行う。

---

## 5. 解決したい課題

- アルコールチェックの記録漏れを減らす
- 記録作業を簡単にする
- 誰が確認したのか記録に必ず残す（各チェックに確認者名を残す）
- 過去の記録を簡単に検索できるようにする
- 管理者が実施状況を把握しやすくする

---

## 6. システム化する範囲

このアプリでは以下を扱う。

- ユーザー管理
- アルコールチェック結果の登録
- 出社時・帰社前の区分
- 確認者の登録
- 検知器使用有無の記録
- 記録日時の保存
- 過去記録の閲覧
- 管理者による記録確認

将来的な追加機能については、
初期バージョン完成後に検討する。

### 画面・操作一覧

ここは**受け入れ条件として先に合意した部分**です。
ログイン時に入力するのは `employee_number`（社員番号）。API パラメータや目印に出てくる
`checker_id` / `data-check-id` / `data-user-id` はいずれも内部IDで、社員番号とは別物
（内部IDと社員番号をどう使い分けるかは `03-設計.md` を参照）。

#### 一般社員

| 操作 | アドレス | 送る項目 |
|---|---|---|
| ログイン画面 | `GET /login` | — |
| ログイン | `POST /login` | `employee_number`（社員番号）、`password`（パスワード） |
| アルコールチェック登録画面 | `GET /` | — |
| アルコールチェック登録 | `POST /alcohol_checks` | `check_type`（出社時 / 帰社前）、`alcohol_value`（測定値）、`checker_id`（確認者の内部ID）、`used_detector`（検知器を使用したか。チェックボックス、既定でON） |
| 自分の記録一覧 | `GET /alcohol_checks` | — |
| ログアウト | `DELETE /logout` | — |

> `DELETE /logout` は HTML フォームからは直接送れないため、Rails の method override（`_method=delete`）を使う。`POST /logout` にしてもよい。

#### 管理者

管理者も通常の社員と同じようにアルコールチェックを登録できる。

加えて、管理者だけ以下の機能を利用できる。

| 操作 | アドレス | 送る項目 |
|---|---|---|
| 全社員のアルコールチェック記録 | `GET /admin/alcohol_checks` | — |
| 社員一覧（当日の実施状況つき） | `GET /admin/users` | — |
| 社員登録画面 | `GET /admin/users/new` | — |
| 社員登録 | `POST /admin/users` | `employee_number`（社員番号）、`name`（名前）、`password`（パスワード）、`role`（権限。`employee` または `admin`） |

- 社員一覧では、社員1人ごとに**その日の実施状況**を表示する。出社時・帰社前それぞれについて「未実施」または実施済み（測定値）を出す。これで「まだ記録していない社員」がひと目で分かる。
- 全社員のアルコールチェック記録（`GET /admin/alcohol_checks`）は、社員・期間・区分（出社時／帰社前）で絞り込んで表示できる。
- 社員情報の編集・無効化・パスワード再発行は初期バージョンのスコープ外とする（登録と一覧のみ）。

### ログイン後の画面

ログイン後はホーム画面を別に用意せず、そのままアルコールチェック登録画面を表示する。

```text
--------------------------------
アルコールチェック
--------------------------------

山田 太郎さん
2026年9月10日

出社時
[ 0.00 ] mg/L

確認者
[ 佐藤 花子 ▼ ]

[x] 検知器を使用した

[ 出社時チェックを登録 ]

--------------------------------

帰社前
未実施

--------------------------------

[ 自分の記録を見る ]

※管理者の場合のみ表示
[ 管理者メニュー ]

[ ログアウト ]
```

出社時をすでに登録している場合は、`check-section start-work` の中に入力フォームではなく、
登録済みの内容（測定値・確認者・検知器使用の有無・登録時刻）を `check-row start-work` として表示し、
同じ区分を二重に登録できないようにする。帰社前も同様。

### 権限

社員には次の2種類の権限を持たせる。

- `employee`：一般社員
- `admin`：管理者

「確認者」はここでいう権限ではない。チェックのたびに実施者が選ぶ役割で、すべての社員が確認者になれる。

一般社員は、自分自身のアルコールチェックの登録と記録確認を行う。

管理者は一般社員の機能に加えて、

- 全社員のアルコールチェック記録の確認
- 社員一覧の確認（各社員の当日の実施状況つき）
- 社員の登録

を行える。

管理者向けのボタンやメニューは、`admin` 権限を持つ社員にだけ表示する。

### 画面につける目印

テストが画面を読むときの目印です。
データの持ち方には踏み込みません。

テーブル名やカラム名は、設計時に自由に決めてかまいません。

- ログインフォームには `class="login-form"` を付ける
- アルコールチェック登録フォームには `class="alcohol-check-form"` を付ける
- 出社時の登録部分には `class="check-section start-work"` を付ける
- 帰社前の登録部分には `class="check-section end-work"` を付ける
- 検知器使用のチェックボックスには `class="detector-used-checkbox"` を付け、既定でチェック済みにする
- 当日の登録済みチェック1件につき `<... class="check-row" data-check-id="（チェックのID）">` を1つ出す
- 出社時の記録には `class="check-row start-work"` のように `start-work` も付ける
- 帰社前の記録には `class="check-row end-work"` のように `end-work` も付ける
- 自分の過去の記録一覧では、記録1件につき `class="check-row"` を1つ出す
- 管理者だけに表示するメニュー部分には `class="admin-menu"` を付ける
- 管理者用の社員一覧では、社員1人につき `<... class="user-row" data-user-id="（社員のID）">` を1つ出す
- 社員一覧の各行には、その社員の当日の実施状況を出す。出社時は `class="check-status start-work"`、帰社前は `class="check-status end-work"` を付け、未実施なら `not-done`、実施済みなら `done` も付ける（例：`class="check-status start-work not-done"`）

これらはテストから画面上の要素を特定するための目印として使用します。

たとえば、テストでは `.alcohol-check-form` を探すことでアルコールチェック登録フォームが表示されていることを確認したり、`.admin-menu` の有無によって一般社員と管理者で表示が異なることを確認したりできます。

### 最初に入っているデータ

`bin/rails db:seed` を実行すると、動作確認に必要な社員が登録されるようにします。

初期データには、一般社員と管理者の両方を用意します。

| 社員番号 | 名前 | 権限 |
|---|---|---|
| `1001` | 山田 太郎 | 一般社員 |
| `1002` | 佐藤 花子 | 一般社員 |
| `1003` | 鈴木 一郎 | 一般社員 |
| `9001` | 高橋 三郎 | 管理者 |

内部ID（DB が自動採番する主キー）は seed 実行時に振られる。社員番号とは別物。

開発・テスト用として、それぞれログインできるパスワードも設定します。

これにより、

- 社員番号とパスワードによるログイン
- 一般社員によるアルコールチェック登録
- 他の社員を確認者として選択
- 出社時・帰社前の記録
- 一般社員と管理者の権限の違い
- 管理者画面

などを開発環境ですぐに確認できるようにします。

※初期データの社員名・社員番号・パスワードは開発用であり、本番環境では実際の社員情報を使用します。
