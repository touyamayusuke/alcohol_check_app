# 02. 要件

`01-要求.md` を読んで、**今回作るもの**を決めます。

要求は「困っていること」でした。要件は「それに対して何を作るか」です。
同じ困りごとに対して、作り方は何通りもあります。そのうちの一つを、あなたが選びます。

---

## 作るもの

> 画面ごとに、そこで何ができるかを書きます。
> 例：「自分の記録一覧 — 自分のチェックだけが新しい順に並び、1件ごとに日時・区分・測定値・確認者が出る」

### ログイン画面

社員番号とパスワードを入れてログインする。間違っていれば入れず、同じ画面にエラーを出す。

### アルコールチェック登録画面

ログイン後はこの画面をそのまま出す（ホーム画面は別に作らない）。

- 上部に本人の名前と当日の日付を出す。
- 「出社時」と「帰社前」の2区分を縦に並べる。区分ごとに、
  - まだ登録していなければ、測定値の入力欄・確認者を選ぶドロップダウン・検知器を使用したかのチェックボックス・登録ボタンを出す。
  - 確認者のドロップダウンには自分以外の社員が名前で並ぶ（自己確認はできない）。
  - 検知器使用のチェックボックスは最初からチェックが入った状態にしておく。通常運用（毎回検知器を使う）では
    何も操作せず登録でき、検知器が使えなかった例外の回だけチェックを外す。
  - すでに登録していれば、入力欄の代わりに登録済みの内容（測定値・確認者・検知器使用の有無・登録時刻）を出し、
    同じ区分の再登録はできない。
- 「自分の記録を見る」リンクを出す。
- 管理者の場合だけ「管理者メニュー」を出す。
- ログアウトボタンを出す。

### アルコールチェック登録

区分（出社時／帰社前）・測定値・確認者・検知器を使用したかを受け取り、
ログイン中の社員のチェックとして、登録日時つきで保存する。登録後は登録画面に戻る。

### 自分の記録一覧

ログイン中の社員のチェックだけを新しい順に並べる。他人の記録は出さない。
1件ごとに日時・区分・測定値・確認者名を出す。

### 全社員のアルコールチェック記録

管理者だけが開ける。全社員のチェックを一覧表示する。
社員・期間・区分（出社時／帰社前）で絞り込める。

### 社員一覧

管理者だけが開ける。全社員を一覧表示する。
各行にその日の実施状況を出す。出社時・帰社前それぞれ「未実施」か実施済み（測定値）かが分かるようにし、
「まだ記録していない社員」がひと目で分かるようにする。

### 社員登録

管理者だけが開ける。社員番号・名前・パスワード・権限（一般社員／管理者）を入れて社員を追加する。
追加した社員は、その社員番号とパスワードでログインできる。

### ログアウト

セッションを破棄してログイン画面に戻る。

### 権限による出し分け

- 管理者のときだけ管理者メニュー・管理者画面を出す。
- 一般社員が管理者用の画面を直接開いても入れない（登録画面に戻す）。
- 未ログインで各画面を開いたらログイン画面に戻す。

### 確認方法の前提（法令対応）

- 本システムが扱う確認は対面のみとする。確認者は「その場にいる社員」から選ぶ設計のため、
  対面であることは仕組み上すでに保証されており、対面／非対面を区別する項目は持たない。
- 安全運転管理者は、社内規程により全社員をあらかじめ補助者として選任済みである。
  そのため、確認者を安全運転管理者・補助者に限定する仕組みはシステム側には設けない。

### 最初に入っているデータ

`01-要求.md` の初期データ（一般社員3人・管理者1人）がそのまま使える前提で動作確認する。

## 作らないもの

> `01-要求.md` に書いていないこと、初期バージョンでは省くことを並べます。
> 作らないと決めた理由も、ひとことで添えてください。あとで聞かれます。

- 測定値の合格・不合格の自動判定（値は記録するだけ。判定は人が画面を見て行う）
- 登録した記録の修正・削除（打ち間違いは運用で対応。記録が後から変わらないことを優先）
- 未実施のリマインド通知（メール・プッシュ）（まず社員一覧で見えれば足りる）
- 社員情報の編集・無効化・パスワード再発行（登録と一覧だけ用意する）
- 部署・拠点の管理（会社全体を1つの一覧で見る前提）
- 直行直帰・出張など、その場に確認者がいない場合の確認フロー（近くに社員がいる前提）
- 使ったアルコール検知器の機種の記録（使用した／しなかったの有無だけを記録する）
- 記録の CSV などへの書き出し

### 作らないと決めた理由

まず「記録が漏れなく残り、誰が確認したかが分かる」状態を最短で作るため。
判定・通知・組織管理・帳票は、実際の使われ方を見てから足す。

---

## 完了条件

> 何を確かめられたら「できた」と言えるか。受け入れテストに書くつもりで箇条書きにします。

- 社員番号とパスワードでログインでき、間違えると入れない。
- 登録画面で出社時のチェックを登録すると、同じ画面に測定値・確認者・時刻が表示され、出社時の再登録ができなくなる。
- 帰社前のチェックも同じように登録できる。
- 確認者のドロップダウンに自分は出ない。
- 検知器使用のチェックボックスは何も操作しなくてもON（使用した）のまま登録できる。チェックを外して未使用でも登録できる。
- 自分の記録一覧には自分のチェックだけが新しい順に並び、他人の記録は見えない。
- 一般社員には管理者メニューも管理者画面も出ない。管理者用の画面を直接開いても入れない。
- 管理者の社員一覧で、その日チェックしていない社員に「未実施」が出る。1件登録すると、その区分の「未実施」が消える。
- 管理者が社員を登録すると、その社員番号とパスワードでログインできる。
- `bin/rails db:seed` で一般社員3人・管理者1人が入り、それぞれログインできる。

---

## 優先順位

> 時間が足りなくなったとき、どれから捨てるか。上（先に捨てる）から順に並べます。

1. 全社員のアルコールチェック記録の絞り込み（一覧だけ出せればよい）
2. 社員登録画面（seed の4人で動作確認はできる）
3. 社員一覧の当日実施状況の表示（社員一覧そのものは残す）
4. 自分の記録一覧（当日分は登録画面で見える）
5. 帰社前のチェック（まず出社時だけでも形になる）
6. 出社時のチェック登録 ← ここは外せない
7. 社員番号とパスワードによるログイン ← ここは外せない

## Claude Code に聞くなら

書き終えたら、こう渡します。

```
docs/02-要件.md を書きました。
「作らないもの」に入れるべきなのに漏れているものがあれば指摘してください。
「作るもの」の中で、要求（docs/01-要求.md）から読み取れないものがあれば教えてください。
まだ実装はしないでください。
```

浮かばないときは、こう聞きます。

```
docs/01-要求.md を読みました。
「作らないもの」を決めるための判断材料になる質問を3つ出してください。
答えは言わないでください。
```
